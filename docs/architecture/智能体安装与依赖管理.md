## 两阶段依赖管理

### 📦 阶段一：智能体安装时（新增）

**触发时机**: 用户在AgentStore点击"安装"按钮

**流程**:
```
用户点击"安装"按钮
    ↓
导航到智能体详情页 (/agent/{agentId}?action=install)
    ↓
AgentDetail检测到action=install参数
    ↓
开始下载智能体文件
    ↓
Footer显示: "下载中 (2/3) 45%"
    ↓
下载完成，开始安装
    ↓
Footer显示: "安装中..."
    ↓
生成manifest.json（包含dependencies数组）
    ↓
Footer显示: "检查依赖..."
    ↓
读取manifest.json.dependencies
    ↓
调用 HybridDependencyManager.installDependencies()
    ↓
Footer显示: "安装依赖 numpy..."
    ↓
安装完成，更新manifest.json.dependency_status = 'installed'
    ↓
Footer显示: "安装完成 ✓"
    ↓
3秒后恢复为: "Python环境就绪"
```

### 🚀 阶段二：智能体首次运行时（现有功能）

**触发时机**: 用户点击"使用"按钮，智能体首次运行

**流程**:
```
用户点击"使用"按钮
    ↓
AgentManager.loadAgent(agentId)
    ↓
读取manifest.json
    ↓
检查dependency_status
    ↓
┌─────────────────────┬─────────────────────┐
│ status = 'installed'│ status = 'pending'  │
│ 或 'none'           │ 或 'failed'         │
│  ↓                 │  ↓                  │
│  直接运行智能体      │  触发自动依赖安装    │
│                    │  (AUTO_DEPENDENCY_  │
│                    │   INSTALLATION)     │
└─────────────────────┴─────────────────────┘
    ↓
如果需要自动安装：
    ↓
显示"智能体初始化中..."
    ↓
后台检查依赖状态
    ↓
自动静默安装缺失的依赖
    ↓
安装成功 → 启用功能
安装失败 → 显示手动选项
```

**依赖来源**: 从 `manifest.json.dependencies` 读取

**适用场景**:
1. 阶段一安装失败，需要重试
2. 依赖被意外删除，需要重新安装
3. 依赖版本冲突，需要重新处理
4. 用户手动清理了依赖，需要恢复

## 依赖管理核心组件

### HybridDependencyManager

**职责**: 智能依赖安装策略

**功能**:
- 检测版本冲突
- 选择安装策略（共享目录 vs 虚拟环境）
- 执行依赖安装
- 更新依赖注册表

**使用方式**:
```javascript
// 阶段一：智能体安装时
const result = await hybridDependencyManager.installDependencies(
  agentId,
  manifest.dependencies,  // 从manifest读取
  (progress) => {
    // 更新Footer进度
    agentStatusBarManager.updateStatusOnly('dependency_install', 
      `安装依赖: ${progress.package}...`);
  }
);

// 阶段二：智能体运行时
const result = await hybridDependencyManager.installDependencies(
  agentId,
  missingDependencies,  // 检测到的缺失依赖
  (progress) => {
    // 更新状态指示器
    this.updateStatus(`正在安装依赖: ${progress.package}...`, 'installing');
  }
);
```

## 依赖状态管理

### dependency_status 字段

**可能的值**:
- `none`: 无依赖需求
- `pending`: 依赖待安装
- `installing`: 依赖安装中
- `installed`: 依赖已安装
- `failed`: 依赖安装失败

**状态转换**:
```
none ────────────────────────────────────────> (无需安装)
  
pending ──> installing ──> installed ──> (正常使用)
                │
                └──> failed ──> pending (重试)
```

## 与现有功能的关系

### AUTO_DEPENDENCY_INSTALLATION.md

**文档说明**: 智能体运行时的自动依赖检测和安装

**适用场景**: 阶段二（智能体首次运行时）

**保持不变**: 该功能完全保留，作为阶段一的补充和容错机制

**关键特性**:
- 自动检测缺失依赖
- 静默安装
- 优雅降级
- 手动安装选项

### PYTHON_ENVIRONMENT_MIGRATION.md

**文档说明**: Python环境目录迁移记录

**历史记录**: 已完成的工作，不受新架构影响

**相关性**: Python环境路径保持不变，继续使用 `src/plugins/embedded/`

```

    ↓
```

```
    ↓
Footer显示: "Python环境就绪"
    ↓
```

#### 7. 首次使用

```
    ↓
```

## 技术实现要点

```
服务端API
    ↓
{
  "dependencies": ["pypdf>=6.0.0", ...]
}
    ↓
AgentInstallManager
    ↓
manifest.json
    ↓
HybridDependencyManager
    ↓
共享目录 或 虚拟环境
```

### 2. 状态同步
```
AgentInstallManager
    ↓
更新 manifest.json.dependency_status
    ↓
AgentManager 读取状态
    ↓
决定是否触发阶段二自动安装
```

### 3. 进度反馈
```
HybridDependencyManager
    ↓
progressCallback({ package: 'numpy', ... })
    ↓
AgentStatusBarManager
    ↓
Footer UI更新
```

## 总结

### 新架构优势

1. **提前安装**: 在智能体安装时就处理依赖，首次使用更快
2. **清晰状态**: dependency_status 明确记录依赖状态
3. **容错机制**: 阶段一失败，阶段二自动重试
4. **用户体验**: 实时进度反馈，状态清晰可见

### 与现有功能的协同

1. **阶段一（新增）**: 智能体安装时主动安装依赖
2. **阶段二（保留）**: 智能体运行时检测和补充依赖
3. **HybridDependencyManager**: 两个阶段共用，策略一致
4. **Python环境**: 完全保持不变，继续使用嵌入式环境

### 开发重点

1. ✅ 从API获取dependencies数组
2. ✅ 写入manifest.json
3. ✅ 读取并传递给HybridDependencyManager
4. ✅ 更新dependency_status
5. ✅ Footer实时显示进度
